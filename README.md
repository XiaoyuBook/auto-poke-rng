# auto-poke-rng

面向宝可梦系列单机作品的自动乱数工具，提供从种子定位到结果验证的一体化工作流。

`auto-poke-rng` 旨在帮助玩家和研究者完成乱数场景中的重复操作：定位可用种子、筛选目标结果、自动执行操作，并对最终结果进行验证。项目采用模块化架构，便于针对不同作品、平台和乱数场景持续扩展。

## 项目状态

项目已接入 C++20 公共视频采集和伊机控运行时：多个预览/识别消费者共享同一视频源，串口保持连接，脚本通过复用的 EasyCon 引擎执行。游戏乱数流程后续接入。设备架构、依赖来源和边界见 [runtime/README.md](runtime/README.md)。

公共 OCR 已接入脚本运行时和 `.IL` 的 OCR 文本标签（兼容旧格式 `searchMethod:107/TESSER_DETECT`）：采用 PP-OCRv6 small，支持简中、繁中、英文和日文。首次安装 `setup:runtime` 会下载并校验模型；候选实测、模型哈希、复现方式和适用限制见 [OCR 选型报告](docs/OCR_SELECTION.md)。

## 开发环境

- Node.js 22.12 或更高版本（当前使用 Node.js 24）
- Windows x64 桌面环境
- VS 2022 C++ Build Tools、Windows SDK、CMake 3.24+
- Python 3.12+（复用 EasyCon 脚本解释器；硬件由 C++ 持有）

安装依赖并启动桌面开发窗口：

```bash
npm install
npm run setup:runtime
npm run dev
```

也可以直接运行 `start-gui.bat`。这个入口会自动设置 `AUTO_POKE_TEST_DEVICES=1`，因此伊机控连接面板会提供“测试手柄（模拟）” mock 串口，适合联调虚拟手柄和按键映射；生产启动不会启用模拟设备。

构建渲染层资源：

```bash
npm run build
```

当前 UI 使用 React + TypeScript + Vite，桌面窗口使用 Electron。`src/` 只负责工作区界面和交互状态，`electron/` 负责桌面窗口与安全的 IPC 边界；后续 C++、Python、视频和设备能力应接入主进程或独立运行服务，不应阻塞渲染层。

当前界面以 `reference/index.html` 为布局依据，采用中性深色主题。侧栏提供首页和脚本编辑；顶部三个图标打开视频源、伊机控连接和通知。脚本编辑器工具栏中的“虚拟手柄”负责启用原版键盘控制并打开独立 Joy-Con 状态浮窗；“按键映射”打开图形化绑定窗口。右下快捷工具在同一个右侧悬浮面板中打开视频预览或日志中心，保持当前工作区可操作。面板支持收起、展开／还原和关闭；再次点击当前工具会收起或恢复面板。

顶部工具按钮的右上角使用统一状态点：视频源和伊机控未尝试连接时不显示圆点，连接失败显示红点，连接成功显示绿点；铃铛仅在有未读通知时显示蓝点，查看通知后清除。悬停提示会说明状态。两个设备默认均未连接。视频源收到首帧、伊机控握手成功后才显示绿点；连接中显示黄点。打开工具不代表连接成功。

脚本编辑采用左侧脚本库、右侧编辑器的布局，日志放在编辑器下方，运行与输入工具放在顶部。桌面应用直接读取项目根目录 `scripts/`：真实文件夹名作为可展开的分类，支持子文件夹，所有分类同时显示，不受左上角游戏环境筛选。列表仅加载 UTF-8 的 `.rng` 脚本；选择文件后编辑器显示其实际内容，搜索可跨文件夹查找。

仓库提供 `scripts/火红/` 和 `scripts/珍钻复刻/` 两组输入预览示例。可直接在磁盘上添加文件夹和脚本，再点击脚本库标题旁的刷新按钮加载；空文件夹也会显示。点击 `+` 选择新建位置，立即创建文件；修改名称后按 `Ctrl+S` 会重命名对应文件并保存内容，同名文件不会被覆盖。切换脚本时保留各自未保存的编辑；刷新会更新未编辑的文件并保留编辑中的内容。外部修改或移除当前文件时会提示，保存失败不清空编辑器。单个文件上限为 1 MB，链接与无法读取的文件会列出提示。

桌面端在停止输入约 350ms 后，使用运行时同一套 EasyCon 编译器检查未保存内容，无需连接设备。首个语法或类型错误会标红对应行，并显示原因与定位按钮；修正后继续检查。库文件错误显示其真实文件和行号，不会误标主脚本。检查服务不可用会显示重试提示，不会冒充检查通过。

编辑器支持 IF、FOR、WHILE、FUNC 及 ELIF / ELSE 分支折叠：点击行号旁箭头或省略标记展开 / 收起，工具栏可全部折叠 / 展开（当前块 `Ctrl+Shift+[` / `]`，全部 `Ctrl+Alt+[` / `]`）。嵌套块可分别折叠，切换脚本保留各自折叠状态；折叠不会改动源码、保存或执行内容。折叠块内的错误会标红块首行，点击“定位错误”自动展开；执行跟随同样会展开当前行所在的块。

运行预览显示当前文件、行号、动作、调用来源和循环次数，自动滚动到绿色执行行；滚轮浏览可暂停跟随。预览使用本次启动的源码，修改草稿或切换文件不会使旧位置错标到新内容。执行到 `lib/*.ecs` 时仍可查看实际执行的源码行；停止或完成会清除运行标记。工具栏“帮助”覆盖输入、等待、摇杆、变量、数组、运算符、条件、循环、函数、库、搜图标签及当前能力限制。

`npm run test:script-editor` 使用模拟伊机控验证离线语法检查、错误定位和修正、执行跟随、循环、源码快照、库文件定位和结束清理；界面截图位于 `node_modules/.tmp/script-editor-review/`。帮助中的完整示例也纳入真实编译器测试。

脚本文件访问通过主进程 IPC 完成；浏览器预览会提示使用桌面应用。旧版 localStorage 草稿仍保留原始数据，但不会自动写入或混入磁盘脚本库。本轮涉及 Electron 主进程与 preload，开发时需要重新启动桌面应用。

视频和日志入口整合在工作区底部状态栏，采用图标加短文字的横向布局。展开的面板对应入口高亮，收起时显示短横线，弹出独立窗口后显示外箭头；悬停可查看操作提示。面板从入口上方打开，始终留出底部状态栏。

视频预览标题栏提供“标签”图标按钮：默认是原有的单画面预览，点击后展开标注布局。左上方为截图后的静态帧画布，右上方为实时画面，两侧等宽、画面上下边缘对齐；左下方为截图、红框搜索范围、绿框搜索目标和搜索参数，动态测试对照区左侧显示实时画面的对应区域，右侧显示保存的标签截图，匹配度与耗时列在下方。两组坐标的 X、Y、W、H 放在同一行。右下方为标签列表与操作说明，仅列表内容超出时在内部滚动，标题与搜索框固定；整个标注界面随窗口高度调整，不整体滚动。独立窗口在标签模式下保留最小编辑尺寸，再次点击图标可收起并恢复预览尺寸与缩放限制；弹出／收回保留展开状态。实时画面和原始分辨率截图已接入，截图在弹出/收回窗口后保留；选择圈选工具后可直接拖动设置搜索范围和目标，模板/颜色测试以及 OCR 文本测试都使用当前截图和实时帧显示结果，保存标签会写入当前脚本目录的 `ImgLabel/*.IL`，标签列表可重新加载已保存的坐标与参数。

面板的左边缘、上边缘和左上角可拖动缩放，并记住调整后的尺寸。桌面端点击面板标题栏的“弹出为独立窗口”，可将视频或日志移出主窗口、跨屏移动，使用系统窗口边框调整大小；独立窗口支持置顶和“收回主窗口”。再次点击对应的快捷工具会唤起已有窗口。日志及筛选条件在弹出和收回时保持同步；关闭独立窗口不会退出主程序，关闭主程序会同时关闭工具窗口。

弹出的工具窗口始终保持在主窗口上方，操作主窗口或打开另一个工具时也保持可见。主窗口仍可正常编辑和点击；如需将工具窗口保持在其他软件上方，可单独开启“窗口置顶”。

- `Ctrl+K` 搜索工具，方向键选择，回车打开，`Esc` 关闭。
- `Ctrl+S` 保存当前选中的脚本文件；运行演示的日志记录所选脚本及其目录。
- 桌面端运行、系统级虚拟手柄和输入录制会调用真实运行时；运行当前编辑内容前请连接伊机控。虚拟手柄默认复用 EasyCon 的 `Esc`（启用／待机）和 `Ctrl + Esc`（关闭并隐藏）快捷键，脚本运行期间自动待机并保留浮窗。仅浏览器模式保留演示。
- 日志可按来源筛选、清空；当前窗口最多保留 500 条。

运行检查：`npm test`。检查覆盖真实文件夹发现、文件读写、目录边界与冲突保护、脚本库选择与搜索、独立编辑缓冲、新建与重命名，以及导航、跨页计时和工具面板。文件读写检查使用临时目录。`npm run test:runtime` 验证设备协议与多消费者行为；`npm run test:devices` 验证实际 Electron 接线，使用明确的模拟设备。实机验收需另行进行。

运行桌面窗口集成检查：`npm run test:electron`。检查会使用独立测试配置与临时脚本目录启动 Electron，验证目录展开、文件选择与保存、真实指针缩放、独立窗口的移动与缩放、弹出／收回、日志同步、窗口置顶及关闭清理，并在 `node_modules/.tmp/panel-window-review/` 保存渲染截图。开发测试入口位于 `tests/run-electron.cjs`，不占用用户脚本目录。

虚拟手柄画面回归：`npm run test:controller-overlay`。使用 C++ mock 串口驱动实际 Electron 浮窗，验证 80/100/120/160 尺寸下的摇杆中心、按钮尺寸、中立高亮、移动、按下、八方向和释放后的画面；截图保存在 `node_modules/.tmp/controller-overlay-review/`。该测试不安装全局键盘钩子。可设置 `AUTO_POKE_TEST_DPI=2` 验证 200% 系统缩放，生成截图在对应的 `dpi-2` 子目录。

## 核心能力

- **种子定位**：根据游戏状态和目标条件搜索、定位候选种子。
- **目标筛选**：按个体值、性格、特性、闪光等条件筛选目标结果。
- **自动操作**：编排并执行重复性的游戏操作，减少手动输入。
- **结果验证**：读取或输入实际结果，与预测结果进行比对，辅助确认操作是否成功。
- **模块化扩展**：将作品差异、乱数算法、操作流程和结果解析拆分为独立模块，降低新增支持的成本。

## 设计方向

项目计划围绕以下层次组织代码：

1. **作品适配层**：封装不同作品的状态读取、乱数机制和操作差异。
2. **乱数与搜索层**：提供种子推断、结果预测和条件筛选能力。
3. **流程编排层**：将定位、筛选、操作和验证串联为可重复执行的任务。
4. **交互与工具层**：为命令行、图形界面或其他调用方式提供统一入口。
