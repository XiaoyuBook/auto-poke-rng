# 按遇敌地点限定精灵名称识别（原创优化，2026-10-07）

本应用生成的火叶流程现在用**游戏版本、实际地点、遭遇方式**限定名称候选。这是本应用的原创行为扩展，改变了原版搜索完整名称库的方式；不能将其描述为原版识别流程的完全等价迁移。

## 候选范围

加载 `加载野生遇敌槽数据()` 时，通过 `OCR名称设置遇敌环境` 把主脚本的实际环境传给本次运行的 `OcrNameRuntime`。主脚本与库文件的全局变量隔离，因此必须显式同步。普通流程、狩猎区、钓鱼以及孵蛋／波克比临时野生 Seed 验证共用这条入口；临时地点切换、恢复定点目标时重新设置，避免沿用旧地点的名单。

名单使用本次运行从 ECS 提取的 `python_wild_data.json` 和 `python_data.json`，与后续反查使用同一份遇敌表、名称表。只读取当前遭遇方式的可达槽位，对物种去重，不读取无效填充槽位，不按出现概率排序或排除低概率物种。

例如当前审计语料中，火红／叶绿的常青森林草丛有绿毛虫、铁甲蛹、独角虫、铁壳蛹、皮卡丘共 5 种。即使目标是绿毛虫，也必须保留其他 4 种，以识别实际抓获物种及非目标闪光。6 号道路的草丛、冲浪及三种钓竿分别使用各自名单，火红与叶绿也分别查表。`All Wild Methods` 的 199 是 RNG 搜索选项，不能当作草丛／冲浪／钓竿的遭遇方式。

此处“当前地点”来自流程配置和执行中的地点切换，并未新增画面定位能力；如果玩家实际起点与配置不符，应修正起点或配置。

## 识别顺序

1. 每次识别开始先清空上一只精灵的 OCR 候选，防止 OCR 不可用或区域错误时复用旧结果。
2. 有完整有效的野生表时，沿用原编辑距离与名称得分公式，对全部本地物种排序。精确名称和尼多兰别名也受地点约束；原别名偏好只有在该物种属于本地名单时才有效。
3. 保留全部本地物种供普通／闪光 Sprite 标签验证，不沿用全库候选的“最多 8 个、距最佳分不超过 1000”截断。即使 OCR 错读成另一个本地精灵，也能继续验证剩余物种。
4. 候选依次按原 `OCR名称闪光匹配度确认` 验证，阈值、标签和未知图腾特殊处理不变。地点名单本身不能证明画面中的物种，也不能证明出闪；后续 `CheckCaptureShiny` 与非目标闪光策略继续执行。
5. OCR 候选均未通过时，仍调用原单字识别。启用地点筛选的情况下，单字结果也在同一名单内纠错并做图像确认，不能绕过限制接受一个猜测。全部失败返回空名称，由原调用方处理识别失败，不伪造物种或抓捕结果。

非野生场景、未知地点、无可达槽位、遇敌／名称表缺失或不完整时清除限制，沿用原全库纠错和原单字回退。不会拿一部分已知物种当作完整名单。没有设置环境的独立调用也继续使用原全库行为。

- 生成器在 `main.ecs`、名称库中标记 `GUI_OCR_ENCOUNTER_SCOPE_V1`，不会修改下载的脚本包。
- `lib/ocr_backup/` 保存本次覆盖前的 `main.ecs` 和两个名称库。主反查迁移的 `python_backup/main.ecs` 继续保留其较早阶段的对照副本。
- `python_ocr_names.json.application_policy` 及 `plan.json.runtime_overrides.python_ocr_names.application_policy` 标明原创策略；文件 SHA-256 和备份路径随快照保存。
- 环境切换输出 `OCR地点筛选` 摘要。完整磁盘诊断中的 `ocr.encounter-scope` 记录环境、表索引、物种名单、候选数及限制不可用的原因；`ocr.name-correction` 同时记录完整库大小、本地范围、实际得分及图像验证候选。

旧生成目录不会自动安装新入口；重启应用并开始新流程后生效。
