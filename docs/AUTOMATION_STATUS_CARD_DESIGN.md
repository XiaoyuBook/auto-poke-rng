# 自动定点流程状态卡片设计提案

2026-09-28：用户已授权开发最新的小圆点回路方案。实施要求以 `AUTOMATION_STATUS_GRAPH_IMPLEMENTATION.md` 为准。本文件第 2 节的直线阶段轨迹、完成勾选、访问次数及其演示均已被后续设计取代，不得照其实现；其余真实流程与数据约束供核对，最终以当前代码为准。

## 1. 真实运行路径

第一轮按配置从测种脚本、捕获 Seed 或当前 Seed 校正开始。后续轮次从测种脚本开始。每轮开始时锁定本轮 delay。

捕获/校正 → 搜索最早可达候选 → 判断距脚本启动帧的距离：

- 距离较远时执行过帧脚本，然后普通校正或完整重测 Seed，再判断/搜索。
- 启用过场时预留过场帧数，执行过场脚本、过场校正，再搜索/判断。
- 进入可等待范围后实时等待；必要时最终校准或调整脚本内部等待，再启动撞帧脚本。
- 撞帧脚本执行与 OCR 判闪可能并行，不应假定脚本先结束才开始判闪。
- 判定出闪：按录像开关执行录像，再结束；录像失败不应掩盖出闪结果。
- 未出闪且走逃跑续搜分支：逃跑、校正、重新搜索，仍在同一轮，下一次撞帧属于该轮的新尝试。
- 走自动反查分支：反查脚本、OCR 个体信息、匹配实际候选、记录 delay 样本，再结束当前轮或下一轮。
- 无候选也可以正常结束一轮；循环次数用尽与出闪是不同结果。
- 普通校正可重试，按配置可同轮补救测 Seed；过场后校正失败另有退出规则，不能统一显示成“重新测种”。

异常也须区分：自动重试中、用户停止、设备/脚本故障、判闪未知且停止等待人工处理。普通物种判闪超时目前可能按未闪继续；御三家/游走的未知结果会停止。界面必须描述实际执行分支，不能把未知显示为确定未闪，也不在 UI 层修改该策略。

## 2. 卡片位置与信息结构

保留当前顶部目标卡片右侧的位置，不新增宽大的看板或移动视频/日志。常规宽度约 440–700px，随内容自然增高，取消上一版 190–230px 的高度约束。阶段轨迹优先保持可读，窄工作区调整排布。

卡片固定结构：

1. 顶栏：流程状态；右侧本轮编号和生命周期状态。有限循环“第 3 / 10 轮”，无限循环“第 3 轮 · 无限”，尚未开始不显示“第 0 轮”。
2. 常驻阶段轨迹：测种 → 搜索 → 推进校正 → 等待触发 → 撞帧判闪 → 结果处理。6 个节点是便于理解的展示分组，不能替代真实状态机，也不表示必须依次经历。
3. 流转说明：节点轨迹下展示最近一次真实转移，回流时用返回方向和简短原因，例如“校正连续失败 ↶ 返回测种（仍为本轮）”。
4. 主标题：正在发生的具体动作，如“等待启动撞帧脚本”“正在采集眨眼”“过场后正在校正”。最新一条日志不直接担任标题。
5. 当前阶段的关键内容：一项主要值与最多 2–3 项辅助指标，或一项真实采集进度。无关、未知指标直接隐藏，不固定堆三个破折号。
6. 一句动作说明：在当前已确定的条件下，接下来将做什么；重试时说明正在自动处理，无需用户操作。
7. 底部低强调入口：“本轮轨迹”，按发生顺序展开本轮真实活动。完整运行详情和日志仍通过已有入口查看。沿用外部开始/停止，不重复摆一排控制按钮。

主卡片不放完整 Seed、脚本全路径、调试时序、全部候选；放进详情窗口或日志。没有全程百分比或默认倒计时。上一版不展示阶段打勾的限制已取消：勾号只能表示“本轮已走过”，不能表示该阶段以后不会再次进入。

### 2.1 节点状态与回流

- 未进入：中性描边圆点和阶段名，不将未发生的阶段自动标为成功。实际跳过的阶段在存在明确跳过事件时显示“已跳过”。
- 当前：柔和强调色实心节点、细外圈与当前阶段文字；任何时刻只有一个主要活动节点。撞帧与判闪共处一个分组，组内分别反映脚本与检测状态。
- 已走过：勾号与低强调色，字面标注“已走过”；重新进入时恢复当前样式并标记“再次进入”。次数来自真实进入事件，不能每次采集或帧数更新都加一次。
- 顺向切换：细线上的光点向实际目标节点移动，约 300–600ms；不会逐个点亮并未经过的中间节点。不得用定时器伪造真实流程进度。
- 同轮回流：光点回到实际阶段，保留已走过轨迹；在回流说明中明确“仍为本轮”。逃跑续搜、普通重试、补救测种都不会自行增加循环轮数。
- 新一轮：收到真实轮次开始事件后更新轮次、清空当前轮节点访问记录；上一轮仍保留在运行历史。停止/失败不将剩余节点自动打勾。
- 结束：仅在结果处理真实完成且设备清理结束后显示完成状态。出闪、未出闪结束、用户停止、故障各有明确文字与对应样式。
- 无候选结束可以从搜索直接进入结果处理，中间节点保留未执行/明确跳过状态；首轮从当前 Seed 校正开始时，测种节点不得自动标已走过。

### 2.2 展示分组映射

| 展示节点 | 对应实际活动 |
| --- | --- |
| 测种 | 测种脚本、完整捕获 Seed、解算、同轮补救完整测种 |
| 搜索 | 候选搜索与重新搜索 |
| 推进校正 | 推进决策、过帧、普通位置校正、过场脚本与过场后校正、逃跑及逃跑后校正 |
| 等待触发 | 最终校准、实时等待、动态调整脚本内部等待 |
| 撞帧判闪 | 撞帧脚本与并行判闪检测 |
| 结果处理 | 自动反查、样本入库、录像、轮次结束判断与运行清理 |

同一个 REIDENTIFY 顶层阶段需要结合活动上下文区分普通、过场后与逃跑后校正；同一个 CAPTURE_SEED 也要区分初始测种、推进后的完整重测、补救测种。最终以活动事件映射，不能仅看阶段枚举或中文日志猜测。

本轮轨迹按时间记录活动与回流原因，可以多次出现同一阶段。静态节点用于快速定位，展开轨迹用于看清实际走法；不把全部底层日志挤进卡片。界面状态聚合至少按 runId、roundIndex、activityId 隔离，并保留可重建的阶段进入顺序。

交互演示包含三条有限模拟路径：过场与逃跑续搜后进入下一轮、出闪录像后结束、校正失败后同轮补救。演示控件位于产品卡片外，实际应用不加入“演示/上一步/下一步”。该样例不是穷尽测试，异常和中止仍按第 7 节验收。

## 3. 分阶段展示

| 实际情形 | 主标题示例 | 主卡片重点 |
| --- | --- | --- |
| 尚未开始 | 等待开始 | 当前运行方式、起点；提示开始前检查。未检查不能直接宣称“已就绪”。 |
| 准备启动 | 正在检查运行条件 / 正在准备运行环境 | 来自真实检查的当前事项；无虚假进度百分比。 |
| 运行测种脚本 | 正在执行测种脚本 | 当前脚本短名称；随后捕获 Seed。 |
| 采集 Seed | 正在采集眨眼 | 实时 captured/target，可绘制仅代表采集的进度条。分母取服务事件，不能固定 40。 |
| 采集完成、解算尚未结束 | 正在解算 Seed | 说明采集已完成、正在解算，不停留在“采集 40/40”并假装全部完成。 |
| 搜索目标 | 正在搜索可达候选 | 搜索范围；找到候选后才显示数量/锁定结果，不虚构搜索百分比。 |
| 运行过帧脚本 | 正在执行过帧脚本 | 本次请求推进量（若有真实字段）、本轮 delay；禁止把上次测量帧数伪装成实时计数。 |
| 普通校正/重试/补救 | 正在校正位置 / 校正重试中 / 补救测种中 | 本次真实采集量与尝试次数；区分同轮补救和下一轮。 |
| 过场 | 正在执行过场脚本 / 过场后正在校正 | 当前动作、校正采集量及重试信息；不能全程停在“过场脚本运行中”。 |
| 最终校准/等待 | 正在校准启动时机 / 等待启动撞帧脚本 | 当前 Adv、脚本启动 Adv、距启动剩余 Adv。 |
| 动态调整 | 正在调整脚本等待 | 调整后的内部等待值可进详情；下一动作是执行撞帧脚本。 |
| 撞帧与判闪 | 撞帧中 · 正在检测闪光 | 脚本运行状态和判闪观测状态分别展示；有结构化事件时区分等待首关键词/第二关键词。 |
| 逃跑续搜 | 未出闪，正在逃跑续搜 | 本轮第几次尝试、真实剩余候选数；说明随后校正并继续本轮。 |
| 自动反查 | 正在反查个体 | 反查窗口、本轮 delay；细分到脚本/OCR/匹配时依赖新增真实事件。 |
| 正在保存录像 | 已判定出闪，正在录像 | 已有出闪结果，但流程仍在收尾，不能宣称控制器已释放。 |
| 出闪结束 | 已判定出闪，流程结束 | 判闪间隔、阈值、录像结果。出闪由检测判定，不是静态候选预测。 |
| 普通完成 | 本次运行结束 · 无候选 / 已完成设定轮次 | 实际结束原因；颜色与“判定出闪”区分。 |
| 用户停止 | 已停止 | 保留停止前阶段和本轮结果，冻结动态显示。 |
| 正在停止 | 正在停止并释放设备 | 在清理完成前保留 stopping，不提前显示已停止。 |
| 需人工确认 | 判闪结果未知，流程已停止 | 明确当前需要人工确认战斗；不提供后端不存在的“继续”功能。 |
| 运行故障 | 因设备断开停止 / 脚本执行失败 | 简短原因与本次日志入口，详细报错放详情。 |

同一个完整流程可能经历“推进 → 校正 → 搜索 → 推进”，因此不能用线性的“第 4/7 步”表示完成度。尝试数与循环轮数也必须分开。

## 4. 时序与数字规则

- 等待阶段主要比较当前 Adv 和脚本启动 Adv，原始目标 Adv 放详情，避免用户误以为要等到原始目标才运行脚本。
- 基础例子：原始目标 11915，本轮 delay 1442，脚本内部等待 70，脚本启动帧为 10403；当前 10309，距启动还有 94 Adv。以 runner 的真实 decision 数据为准，不能 UI 重新扣减。
- Adv 是 RNG 推进量，不是视频 60 FPS。不要用 Adv/60 换算秒。
- 自动定点目前没有通用可靠的绝对启动时刻字段。现有 wait_target_wall 主要来自 TID；卡片不复制“距取名启动”或伪造秒级倒计时。
- 如果以后显示预计秒数，必须由对应线性/Timeline 计时器提供并标注预计，不能仅解析日志里的估算秒数。
- 本轮 delay 在重测、过场、逃跑续搜中保持冻结；卡片显示运行中的实际值，不读正在编辑的下一轮策略预估。
- 每次进入新采集、解算、搜索或清除旧目标后，清理/隐藏不再有效的旧指标。停止后明确属于最近一次运行。

## 5. 当前数据能力与需要补的事件

已有可用数据：

- state.status/runId/message、progress.phase/loop_index/current_advances/raw_target_advances/trigger_advances/remaining_to_trigger、state.roundDelay。
- 捕获事件 captured/target；seed；轮次历史 cycle_start、candidates_found、candidates_refiltered、cycle_result、attempt_result、target_missed、reverse_result 等。
- logs 与 run.startedAt/endedAt、round.outcome/interval/usedDelay/actualDelays。

必须注意的限制：

1. phase 和 log_message 不总是讲同一件事。例如进入 SEARCH_TARGET 时日志可能还是“seed 捕获完成”。Electron 还会在日志为空时沿用旧 message。因此标题应由规范化阶段产生，说明和日志另外处理。
2. capture 不随每个阶段自动清空；不可跨阶段显示旧的 captured/target。建议采集事件绑定活动 id，开始/结束显式上报。
3. 首轮测种脚本执行期间 loop_index 可能还没刷新，而 cycle_start 已发生。统一使用运行中的轮次事件，修正事件时机，不在前端随意加一。
4. 尝试次数、计划推进量、普通/过场/逃跑后校正区别、重试序号目前部分只在内部变量或日志里，需结构化上报。
5. 撞帧与判闪没有独立的顶层 phase；host 的判闪事件当前转换成日志。应把已有 DialogTimingEvent 结构传至状态层，保留脚本与监测的并行关系。
6. 反查子阶段、录像开始/成功/失败需要对应服务事件。没有事件时展示诚实的“反查中”等概括标题，不靠时间猜测已进入 OCR 或正在录像。
7. 状态目前主要按 kind 判断，没有完整流程 id 与运行目标快照。需将 flowId/name、目标、循环模式/上限绑定 runId；查看其他配置时标明“上次运行：某流程”，不得把 A 流程结果显示成 B 流程。
8. 捕获成功后解算阶段的起止、活动时间戳、需要人工处理的原因应结构化，不以中文日志正则作为长期状态协议。

建议最小化扩展运行活动快照：在保留现有 phase 的基础上补 activityKind/substage、activityId、roundIndex、attemptIndex、retryAttempt/retryLimit、requestedAdvances、scriptStatus、captureStatus、shinyObservation、recordingStatus、resultKind/reason，以及运行配置身份。字段按实际需要逐项落地，并在操作发生的位置发事件。不改 RNG 算法。

## 6. 展示与交互规则

- 中性：待命、普通完成、用户停止；强调色：正常进行；琥珀色：正在重试/需要处理；绿色：已判定出闪；红色：实际运行故障。颜色旁必须有文字。
- 只有用户确实需要操作时显示“需要处理”。自动重试中说明“正在自动重试”，避免诱导用户打断。
- “运行详情”建议用现有 Dialog，显示本次运行身份、当前/最后阶段、Seed、锁定目标、启动帧、本轮 delay、脚本内部等待、脚本与最近事件，主卡片保持紧凑。
- “本次日志”按 runId 与轮次定位已有日志中心；不要仅跳转到所有日志。
- 普通阶段切换不抢焦点，实时帧数不逐帧触发屏幕阅读器播报；只在阶段/结果变化时轻量通知。
- 其他流程占用或独立判闪校准使用独立文案；判闪校准不能冒充自动定点第 1 轮。

## 7. 设计验收边界

覆盖三种启动方式；采集/解算；无候选；普通重试和同轮补救；过场校正；等待触发；动态调整；并行撞帧/判闪；逃跑同轮续搜；反查/样本保存；出闪录像成功/失败；普通完成；用户停止中及停止完成；设备中断；需人工确认；切换配置后的历史结果归属。

检查过帧脚本期间不显示虚假的实时帧数或百分比，采集总数来源正确，当前/启动/原始目标不混淆，未知判闪不被写成确定未闪，旧事件不覆盖新 runId/activityId。只做模拟与隔离测试，不操作真实游戏。
