# 上次连接与快速重连设计

状态：已实现侧栏快捷重连、成功配置持久化、失败提示及可选启动重连。
日期：2026-10-04。

2026-10-04 用户修订：采用侧栏顶部的同级快捷图标。点击直接按上次配置连接；只在失败时显示无需确认的提示，失败设备图标右上角保持红点。以下入口与反馈规则已按这一方向更新，原顶部快捷条和底部快捷卡不再作为默认方案。

## 用户体验

首次连接视频源、伊机控或音频成功后，软件自动记住对应设备及参数。下次打开软件，在主窗口点一次「按上次重连」即可恢复这些连接，无需再次进入两个设备窗口。

提供「启动时自动重连」开关，首次默认关闭。用户打开后，下次启动自动执行同样的流程；界面就绪后后台连接，不阻塞主窗口。

只恢复设备连接。脚本、自动流程及控制输入仍由用户主动开始。

## 入口方案

在侧栏顶部的 `GlobalTools` 内增加「按上次重连」图标，与视频源、伊机控、通知同级。建议顺序为视频源、伊机控、重连、通知；重连使用插头带闪电图标，悬停或键盘聚焦显示「按上次重连」。图标与现有工具使用相同尺寸和间距，不增加常驻卡片或摘要。

点击立即执行重连，不先打开详情、不要求确认。正在连接时重连图标显示加载状态并禁用重复点击；连接结束后恢复正常，可再次补连失败项。所有设备已在线时点击只保留当前连接，不重复打开。

每个设备的图标右上角表示真实状态：未连接无点，连接中黄点，已连接绿点，失败红点。重连图标是操作入口，不额外复制各设备状态。提示消失后红点继续保留，只有连接成功后变绿，或明确断开/清除状态后回到无点。悬停或键盘聚焦失败图标可看设备名称与失败原因。

仅在重连失败时弹出非模态提示，不遮罩、不抢焦点、没有「确定」按钮。一批连接全部结束后聚合一次提示，列出每项失败的名称与简短原因；已经成功的设备继续工作。建议 8 秒后自动消失，可提前关闭；鼠标停留或键盘聚焦提示时暂停消失。可以提供可选的「重试失败项」或「打开设置」操作，它们不是关闭提示的必需步骤。

现有「视频源」「伊机控」图标继续打开对应设置窗口，失败时也保持原有点击行为。再次点击重连图标仅补连未在线设备。首次使用没有任何成功配置时只显示「请先配置设备」的轻量提示，通过既有设备图标完成首次连接，不擅自选择第一项。

游戏音频仍在视频源窗口内设置；若参与重连而音频失败，视频源图标作为入口组显示红点，并在悬停文字中明确区分「视频已连接，游戏音频失败」，失败提示也明确写出音频，不把视频本身伪装为失败。启动自动重连等可选偏好放在设置中，不增加启动确认。

侧栏折叠时仍保留这组工具的原有排列方式。交互元素须设为不可拖动，确保顶部仍可拖动窗口。

## 保存规则

| 设备 | 保存内容 | 成功判定 |
| --- | --- | --- |
| 视频 | 设备 ID、名称、采集后端、请求分辨率、请求帧率 | 状态变为 connected，收到首帧 |
| 伊机控 | 上次成功的串口、显示名 | 原连接流程完成握手并发布 connected |
| 音频 | 明确选择且成功连接的端点 ID、名称 | 原音频服务确认 connected |

各设备独立维护上次成功配置；不用等待三项同时成功。保存原始请求参数，实际采集分辨率等只用于展示，避免设备协商结果覆盖用户设置。

表单里未连接成功的选择属于草稿。选错、失败、取消和枚举列表的默认第一项，都不得覆盖上次成功配置。重新打开设备窗口优先预填已保存的配置；设备已在线时展示当前连接的真实参数。

断开连接和设备暂时不存在不会清除记忆。第一版恢复所有有成功记录的设备；各设备的「参与重连」及「忘记上次连接」可作为后续扩展，当前尚未提供。音频没有成功记录时不参与重连，不能自动选择电脑麦克风。QQ 通知沿用自身配置，不纳入本次设备恢复。

启动自动重连开关属于独立偏好，不从实时连接状态推导。配置保存于 Electron userData 下的 `device-connections.json`。

## 重连规则

1. 主进程读取保存的偏好和成功配置；没有记录时显示「先设置设备」。
2. 建立一次重连批次，先对参与的设备执行枚举并核对 ID。
3. 三项设备独立处理，使用独立的既有服务；一个失败不取消其余连接。
4. 已在线的设备保留并跳过，不重新打开。实际连接与保存目标不同也保留当前设备，不自动切换。
5. 正在连接的设备由原操作继续完成，不重复发起。同一时刻全局只允许一个重连批次，避免反复点击、多个窗口或 React 重新挂载导致重复连接。
6. 发起 connect 后以真实设备状态更新界面，不把 IPC 返回视作设备已经成功，尤其视频的 start 返回早于首帧。
7. 每项操作沿用既有超时与取消机制，最终进入成功、失败、找不到设备或已跳过状态。聚合状态只包含参与重连的项目。
8. 部分失败时重连图标恢复可点击，悬停提示「按上次重连」；再次点击仅处理未在线项，已成功的会话保留。失败通知中的「重试失败项」执行同样的意图。
9. 用户可在对应设备设置里取消正在连接的单项。取消仅影响该项操作；用批次编号忽略旧操作的迟到结果。取消属于用户操作，不作为连接失败再次弹出错误通知。
10. 脚本、自动流程、录制或设备归属正在占用连接时，暂停受影响的重连并显示原因，不停止正在运行的任务来强行重连。

用户主动断开后，本次打开期间不会后台自动再连。启动自动重连只在主程序启动执行一次，不因弹出/关闭窗口、切换页面、设备状态订阅或手动断开再次触发。运行中意外掉线第一版提示并提供重试，不无限循环重试；重新连接也不自动恢复已中断的脚本。

## 设备身份变化

视频当前使用 Media Foundation 的 symbolic link 或 DirectShow 的 DevicePath/moniker 作为 ID，重连应按 ID 重新枚举，不能保存列表序号。更换后端需要用户明确操作。

伊机控当前枚举仅提供 COM 口名称，没有 USB 硬件身份。第一版可记住 COM3 等上次端口；端口不存在时提示重新选择，不自动连接其他端口。即使同一 COM 口仍在，当前接口也不能证明它仍是同一块单片机，成功握手只能验证兼容协议；这是第一版的明确限制。

后续如需支持换 USB 插口后自动找回伊机控，需要扩展 Windows 设备枚举以返回实例 ID、VID/PID、可用的序列号。匹配唯一、身份充分可靠时才能自动映射到新 COM；多台同型号无唯一序列号时要求用户选择。不能以相同显示名或 VID/PID 直接认定同一台设备。

## 文案与状态

| 场景 | 重连入口 | 反馈 |
| --- | --- | --- |
| 首次使用 | 图标可点击 | 轻量提示先通过既有设备图标完成连接 |
| 有成功记录、尚未连接 | 按上次重连 | 点击立即连接；成功不弹窗 |
| 批次进行中 | 加载图标，禁用重复点击 | 对应设备显示黄点，悬停可查看状态 |
| 全部参与项已连接 | 正常图标 | 对应设备绿点；再次点击不重开连接 |
| 部分失败 | 正常图标，可再次重试 | 成功项绿点，失败项红点；聚合一条非模态通知 |
| 保存设备未找到 | 可重试 | 通知列出设备名，提示检查连接或重新选择 |
| 串口被其他程序占用 | 可重试 | 通知注明串口被占用，请关闭占用程序后重试 |
| 运行中的设备断开 | 可重试 | 红点和原流程真实状态继续显示，重连后不自动恢复脚本 |

启动自动重连全部成功只更新图标状态。失败沿用上述非模态提示，不自动打开设备设置。音频不参与时不计入失败或总数。

## 实施落点

- 新增主进程连接偏好存储，文件放在 Electron userData，提供版本号、字段校验、损坏数据降级、原子写入。只保存配置，不保存 session、预览 URL、音频 token 等运行凭据。
- 在 `electron/devices.cjs` 对手动连接和重连统一捕获请求，等 connected 状态确认后保存成功配置。音频配合 `electron/audio-devices.cjs`。
- 主进程负责单次启动恢复、批次互斥、取消、超时、占用校验和全窗口广播；渲染进程只展示和发出意图。
- `electron/preload.cjs` / `src/devices.ts` 增加偏好查询、偏好保存、重连与结果订阅接口，单项取消沿用原断开接口，不向渲染层暴露任意文件读写。
- `src/components/VideoSource.tsx`、`EasyConConnection.tsx`、`AudioSource.tsx` 使用保存记录预填，并保留未找到的选项提示，不偷偷切换到列表第一项。
- `src/components/GlobalTools.tsx` 增加同级重连图标，沿用现有状态圆点；`src/App.tsx` 接收主进程重连结果并聚合非模态失败通知。不由 `useDevices` 或独立预览/手柄窗口触发启动恢复。
- 保留现有各设备状态含义，额外维护本次重连进度与错误原因，不把持久记录伪装成当前在线状态。

## 验收重点

- 完全退出并重启，点击一次即可按上次参数连接；不用先打开连接窗口。
- 开启自动重连后主窗口可以直接使用，关闭后不会连接；独立窗口不重复触发。
- 视频 connect 返回但首帧未到时仍显示连接中，不提前保存或显示成功。
- 伊机控未插好时视频仍成功；插好后单项重试不会重启视频会话。
- 设备 ID/COM 变化、多个同名设备、音频没有配置时均不会误选其他设备。
- 误选后连接失败、取消、断开、配置文件损坏不会把无效草稿当作上次成功记录。
- 重复点击、迟到的状态、关闭提示、取消单项和运行占用均不会引发重复连接或停止现有任务。
- 点击重连前不出现确认或设置窗口；全部成功后也不弹窗。
- 失败通知不抢焦点、不需确认；自动消失后对应设备红点仍在，多项失败在同一条提示中列出。

实现入口为 `electron/device-reconnect.cjs`、`GlobalTools` 和 `ConnectionNotice`。重启软件后，先成功连接一次设备即可建立记忆。开发中的旧进程不会补写升级前的连接记录。

验证命令：`npm run test:devices:reconnect`、`npm run test:devices:reconnect:electron`。后者使用独立临时用户目录，依次测试失败提示、跨进程重启恢复、原生视频连接或被另一实例占用的失败分支；不会退出正在运行的软件。测试使用模拟串口和原生合成音视频，真实采集卡、真实串口仍需硬件验收。
