# 普通目标自适应候选细分（原创策略，2026-10-07）

此功能是本应用的原创行为扩展，**不是原版 ECS 行为的等价迁移**。适用于应用生成的正式版与时间轴版普通野生／定点流程。御三家不吃糖、孵蛋及波克比特殊 Seed 复核继续使用各自原流程。

## 为什么改变

2026-10-07 以绿毛虫为目标的运行完成了 13 轮捕获，实际也抓到了独角虫和铁壳蛹。第 1、6 轮分别反查到 EBC0 / 25211 ADV 和 BD96 / 25290 ADV；其他 11 轮初始观测有 6–113 个候选。LV3–5 的能力值提供的信息有限，TV 模式 ±1000 ADV、Seed ±20 的窗口会保留多个可能落点。

此前应用生成器的共同区补丁在候选达到 5 个时直接结束细分、改用跨轮筛选。共同区未能消歧就进入下一轮，因此这些轮次没有继续喂糖。原细分流程另有每只 8 颗糖、候选一次不减少即停滞等退出条件；独立唯一解也没有提交共同区历史。

“已反查”不一定代表独立唯一：离线回放第 1 轮 LV7 观测仍匹配 EBC0 的 25211 与 25217 两个 ADV，旧流程选中了 25211。新策略会保留这两个落点；六项 IV 相同则结束无效喂糖，等待其他遭遇的共同区证据，不能把旧的已选中摘要直接作为真值锚点。

8 颗不是精度保证。按当前能力值公式，攻击种族值 30、努力值 0、性格无修正时，攻击 IV 0 与 1 在 LV3–11 每一级的能力值都相同，到 LV23 才第一次区分。连续几次候选数量不变不能证明后续升级无效。

## 新的决策顺序

1. 保留本次扫描的候选，包括 Seed 索引、ADV、实际生成方法、完整六项 IV 和原候选诊断。All Wild Methods 的 199 是搜索选项；选中的实际方法始终是 101／102／104。
2. 所有候选给出同一个 Seed／ADV 时，认定为独立唯一落点。方法重复不会制造不同落点。
3. 否则，尝试用之前遭遇的共同区选出当前观测的唯一配对。当前宽候选组尚未提交，不能先为自身增加证据再证明自己。选中候选直接回写原校准门控，保留实际生成方法；原剩余帧冻结条件继续优先，不再执行旧共同候选重生成。
4. 仍有歧义时，用当前物种、性格、努力值和剩余候选 IV 逐级预测至 LV100，找出最早能使候选能力值产生差异的等级。保留原能力值整数公式及性格项顺序；不修改 Seed／帧搜索范围或识图阈值。
5. 有后续信息且预算足够，则沿用原 ECS 的单颗糖果导航、读取六项能力值、累计 IV 范围求交和反查扫描。每一级仍观测并复核；预测不会代替实机识别，也不会批量跳过中间等级。
6. 无法继续时，记录“待消歧”，提交最终完整候选组后重启下一轮；不按路径猜一个落点，也不下发本轮校准。

如果剩余落点具有相同六项 IV，升级无法区分，立即转入跨轮证据。候选保存超过 4096 条、等级未增加、糖果用完／使用失败、达到等级或资源预算等也会明确退出。已存在的无匹配、识图失败及 IV 交集为空分支仍由原流程处理，不能当成成功校准。

## 预算与证据

“运行与反查校准 → 高级反查与校准参数 → 候选细分预算”随当前存档保存，并在生成新运行时冻结：

| 参数 | 默认值 | 范围与含义 |
| --- | --- | --- |
| `refinement_candy_budget` | 0 | 0–99；0 表示按信息量继续，最高 LV100；正数为本只糖果总预算 |
| `refinement_time_budget_ms` | 600000 | 1000–21600000；界面用秒显示，默认每只 10 分钟 |

下一次有效观测所需糖果已超过剩余预算时提前结束，避免消耗糖果却到不了有信息的等级。耗时预算在每次观测决策处检查，不打断执行中的一颗糖果或一次扫描。取消请求仍使用宿主 checkpoint。

同一只宝可梦的各次升级扫描只保留最终一组共同区证据；不会把宽候选组和升级后的窄候选组当成多轮。独立唯一解也参与共同区历史。候选直方图沿用原每候选投票，但升级重扫先恢复本只开始前的直方图，再记录本次扫描，因此同一候选不会因多吃糖而重复加票。共同区原有去重、容量及多数覆盖条件继续有效。

## 原版与应用扩展边界

| 部分 | 行为 |
| --- | --- |
| 原库查表、LCG、生成方法、能力值／IV 公式、野生槽位和初始等级验证 | 保持计算迁移的差分验证 |
| 普通目标候选 ≥5 直接退出、8 颗上限、一次候选停滞、路径投票提前停糖 | 由本应用的信息量决策与明确预算取代 |
| 原 ECS 喂糖按键、等待、页面导航与识图 | 继续复用 |
| 御三家、孵蛋、波克比特殊 Seed 复核 | 不启用本策略 |
| BINGO 稳定簇与 ±4 图内计数 | 保持原条件；新增展示用反查／图外记录数 |

`frlg_candidate_refinement.py` 在主反查迁移末尾安装 `GUI_ADAPTIVE_REFINEMENT_V1`，不会编辑下载的源脚本包。`python_backup/main.ecs` 保留安装这次策略前的生成结果，`python_main_reverse.json.application_policy` 和 `plan.json.runtime_overrides.candidate_refinement` 标识原创策略与冻结预算；预检日志包含新模块 SHA-256。纯计算差分通过只证明计算部分一致，不证明新停止策略与上游等价。

## 日志和显示

完整磁盘日志记录 `FRLG_REFINEMENT|V=1`：候选条数、不同 Seed／ADV 落点数、当前等级、已用糖果、下一有效观测等级、状态及原因。精简日志显示可读摘要；轮次详情显示喂糖进度和“待消歧”，不再仅写“已结束”。

BINGO 的反查记录和图外次数是展示指标，随分布清空而重置；图外落点不进入原二维图计数，也不作为稳定簇样本。旧日志不能补回未记录的完整候选集合或升级后的真实能力值。重启应用并开始新流程后生效，运行中的 Python 子进程和旧生成目录不会自动更新。
