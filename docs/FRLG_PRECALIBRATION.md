# 目标出闪预校准与日志恢复

2026-10-04：修复普通野生／静态流程出闪即停时不保存预校准的问题。

## 保存规则

旧实现只在反查确认完整目标命中时输出保存标记。关闭“出闪后继续抓捕”时，目标获取返回后直接结束，未进入反查，因此即使出闪也会提示“没有完整命中记录”。

现在正式版和时间轴版在每次目标获取前清空最近出闪状态，返回后检查已有图像判闪结果及图鉴编号。仅当已确认闪光且编号与生成方案目标一致、正式轮次大于 0、启用“更新预校准”时，输出 `PRECALIBRATION_UPDATE`，附加 `EVIDENCE=TARGET_SHINY` 与目标／观察编号。执行修正取当轮的 `Seed累计修正索引` 和 `消耗帧实际执行修正量`，不增加按键或等待。

流程正常结束后，宿主校验生成清单中的目标编号及上下文，原子写入当前存档的 `precalibration.json`。脚本因目标出闪主动返回属于正常完成；用户点击停止、设备异常或执行失败不保存。非目标闪光、音频实验候选和第 0 轮均不触发此路径。孵蛋仍使用原有完整命中规则。

文件保留来源 `evidence.kind`：

| 来源 | 含义 |
| --- | --- |
| `full_target_hit` | 反查确认完整目标命中，优先于出闪观察 |
| `target_shiny` | 软件图像确认目标出闪，复用当轮执行修正 |
| `user_confirmed_target_shiny` | 用户确认旧日志中的出闪对象，由日志和运行快照恢复 |

目标出闪说明这组修正曾成功产生目标闪光，可作为下次校准起点；没有反查就不声称实际 Seed、帧、PID 和 IV 已精确命中方案。轮次记录显示“目标出闪”及执行修正，不填造反查落点。后续反查确认完整命中时，使用该记录的修正。旧 schema 1 的无来源记录继续兼容。

文件位于用户数据 `frlg/profiles/<profileId>/precalibration.json`。游戏、Switch 机型、Seed 模式、正式／时间轴入口、流程类型及启动方案须一致，且开启“更新预校准”，新生成的工程才会加载；已有运行工程不会自动更新。
