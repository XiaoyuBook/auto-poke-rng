# 脚本仓库

官方发布源：<https://github.com/XiaoyuBook/auto-poke-rng-scripts>。

## 使用

脚本编辑 → 脚本库标题旁“脚本仓库”。左侧按游戏版本分类，默认选择主界面当前游戏；中间浏览包与用途目录，右侧阅读使用说明或文件列表。界面将 `BDSP` 显示为“珍钻复刻”，不改动原脚本文件名。可搜索名称、作者、用途或文件名，并筛选已安装包、确有更新的包。

选择包 → 预览安装 → 核对变更及冲突 → 确认安装。浏览说明和文件不会安装或运行脚本。“导入脚本包”支持官方 `packages/` 中的 ZIP，使用同一套预览和安装流程。文件作为完整包安装，以保留配套标签。

首次打开先展示内置目录并尝试检查更新；之后使用所选渠道的本地缓存，点击“检查更新”刷新。联网失败时仍可浏览，错误区提供中文提示、重试和切换渠道入口。内置快照不代表最新发布状态，通过 `node tools/sync-script-catalog.mjs <官方 catalog.json 路径>` 更新。

珍钻复刻官方包当前为 `0.0.1` 测试版，包含 24 个 `.txt` 脚本、7 个 `.IL` 图像标签、来源许可证、使用说明与用途分类；测试阶段按 `0.0.x` 递增，正式上线时发布 `1.0.0`。其中 23 个脚本与冻结原版逐字节一致，另一个是本项目的 `OCR翻页.txt` 辅助脚本。只在旧配置请求不存在的 `.rng` 时尝试同名 `.txt`，也兼容仍只有旧扩展名的个人目录。新建脚本使用 `.txt`。

早期误标 `1.0.0`、`1.0.1` 的试验包已从当前发布目录撤回，Git 历史保留原文件。客户端继续禁止降级：曾安装这些试验包的测试环境，如需重新安装 `0.0.1`，先停止脚本并关闭客户端，备份用户脚本目录，将 `BDSP/.rng-package.json` 移到脚本目录之外保存；保留原脚本和标签，重开客户端并检查更新，再预览安装测试包并保留本地修改。

下载、安装不会执行脚本。安装后在脚本库编辑，在自动流程中选择对应文件；个人 OCR、眼睛模板、延迟和任务配置不由包覆盖。

## 用户文件与更新

主窗口、自动流程、标签编辑与分离视频窗口共用 `app.getPath('userData')/scripts`。首次初始化将旧项目 `scripts/` 完整复制到该目录，保留个人文件内容，不删除源目录。以后启动不再重复复制，避免恢复用户已删除或修改的文件。

安装元数据为包目录中的 `.rng-package.json`，记录上游文件哈希与已安装版本。通过当前文件、已安装基线、待安装版本三方比较识别本地修改（含用户删除的文件和标签改动）。默认保留冲突文件；选择“备份后使用仓库版本”才替换冲突。包外个人文件保留。新版本移除的旧包文件只有在未被个人修改时才默认删除。

更新先写临时完整目录，再将旧目录移动到 `userData/script-repository/backups/`，最后替换安装目录。失败会回滚；中途退出时根据安装日志在下次访问仓库时恢复。备份位置显示在安装结果与日志中心，备份不会自动清理。关闭程序会等待正在执行的文件事务结束。

脚本保存、标签保存与包安装共享写锁。手动脚本和自动流程运行期间禁止安装，更新期间禁止启动脚本。未保存的编辑缓冲阻止界面确认安装；磁盘在预览后改变时必须重新预览。

## 发布格式

索引 `catalog.json` 使用 `schemaVersion: 1`，列出名称、ID、版本、最低应用版本、游戏、作者、安装目录和 ZIP 地址、大小、SHA-256。可附带 `readme`、`updatedAt` 和逐文件清单（含 `category`），用于安装前浏览；旧索引缺少清单时从校验通过的版本包中读取。ZIP 包含 `manifest.json` 与 `files/`，描述清单逐文件记录大小和 SHA-256。说明以 Markdown 渲染，忽略原始 HTML 并限制链接协议。

下载限定两个官方源；校验大小、哈希、路径、扩展名和最低版本。拒绝穿越目录、符号链接、大小写冲突、未声明文件和超量解压。手动检查并确认更新，未实现后台自动更新、卸载、自定义仓库和分享链接。

仓库设置可选择 GitHub 或 Gitee（`https://gitee.com/shekongsk/auto-poke-rng-scripts`），选择会持久化，两个渠道的目录缓存分别保存。公开下载不需要用户输入令牌。切换渠道不修改已安装文件，尚未确认的安装预览会失效。

桌面下载使用 Electron 的网络会话，遵循系统代理设置。GitHub 原始文件地址不可达时尝试同一仓库的官方接口；Gitee 允许一次跳转到官方 `raw.giteeusercontent.com` 的同路径 HTTPS 资源，跳转前后共用下载超时，继续执行大小与哈希校验。失败时可切换渠道，或导入已下载的压缩包。网络通道回归：`node tests/run-electron.cjs script-repository-network-electron.cjs`。

## 验证

`npm run test:scripts:repository` 覆盖完整包安装、真实 `.txt` 编译、旧后缀兼容、离线缓存、三方冲突、备份与回滚、中断恢复、迁移失败、IPC 隔离、包校验与界面确认流程。Electron 集成测试：`npm run build` 后执行 `node tests/run-electron.cjs script-repository-electron.cjs`。

新增验证包括中文游戏分类、当前游戏默认值、用途树和文件列表、安全说明渲染、离线浏览与重试、Gitee 渠道持久化及缓存隔离。脚本仓库的 Gitee 同步工作流引用仓库级 Secret；主项目的同名 Secret 不会继承。已配置脚本仓库凭据，并验证实际同步推送及两渠道的下载、校验和安装。

测试版本编号调整属于一次性发布配置，不新增固定版本号的回归测试；通过现有构建及仓库测试、重复构建哈希一致性、索引与 ZIP 清单一致性、脚本及标签逐字节比较，以及两个公开渠道的临时目录安装验证。
