# 脚本仓库

官方发布源：<https://github.com/XiaoyuBook/auto-poke-rng-scripts>。

## 使用

新安装时脚本库为空，应用不附带游戏脚本或图像标签。脚本编辑 → 空脚本库中的“浏览脚本仓库”，或脚本库标题旁“脚本仓库”。左侧按游戏版本分类，默认选择主界面当前游戏；中间浏览包与用途目录，右侧阅读使用说明或文件列表。界面将 `BDSP` 显示为“珍钻复刻”，不改动原脚本文件名。可搜索名称、作者、用途或文件名，并筛选已安装包、确有更新的包。

选择包 → 预览安装 → 核对变更及冲突 → 确认安装。浏览说明和文件不会安装或运行脚本。“导入脚本包”支持官方 `packages/` 中的 ZIP，使用同一套预览和安装流程。文件作为完整包安装，以保留配套标签。

首次打开先展示内置目录并尝试检查更新；之后使用所选渠道的本地缓存，点击“检查更新”刷新。内置目录索引只含说明、文件名与校验信息，不含脚本正文、图像标签或 ZIP，浏览和刷新不会安装脚本。联网失败时仍可浏览，错误区提供中文提示、重试和切换渠道入口。内置快照不代表最新发布状态，通过 `node tools/sync-script-catalog.mjs <官方 catalog.json 路径>` 更新。

珍钻复刻当前提供 24 个独立功能包，版本 `0.0.2`，安装到 `珍钻复刻/<功能>/`，各包可单独安装和更新。红圣菇、美梦神各自带 4 个必需 `.IL` 标签，位于自己的 `ImgLabel/`；其余包无图像标签。各包附来源许可证及使用说明。测试阶段按 `0.0.x` 递增，正式上线时发布 `1.0.0`。24 个脚本均保留旧包中的 `.txt` 文件名和字节，其中 23 个与冻结原版一致，另一个为本项目的 `OCR翻页.txt` 辅助脚本。

旧 `bdsp-official/0.0.1.zip` 保持不可变，供恢复；索引不再推荐大包。已装大包（含早期误标 `1.0.x` 的测试包）可直接按需安装新的独立 ID，不需要移除旧记录。预览列出要从 `BDSP/` 迁移的文件并检查个人修改、删除；源文件原样保留，未使用的 3 个旧标签不会带入新包。已迁移的旧脚本在库中隐藏，避免编辑备份却执行新文件；未迁移的脚本和个人标签不受影响。

包中的 `legacyPaths` 声明旧资源路径。安装后自动流程的已有匹配配置保存为新路径，当前编辑器选择也跟随迁移；若配置写入失败会提示，并可重新打开仓库重试。执行器依据已安装包记录兼容旧 `.txt`／`.rng` 路径，包括文字识别翻页辅助脚本；只在新文件存在时建立对应关系。手动创建的其他路径与空配置不修改。

下载、安装不会执行脚本。安装后在脚本库编辑，在自动流程中选择对应文件；个人 OCR、眼睛模板、延迟和任务配置不由包覆盖。

## 用户文件与更新

主窗口、自动流程、标签编辑与分离视频窗口共用所选脚本根目录，默认 `app.getPath('userData')/scripts`。已有目录直接保留；新安装创建空目录。仅在用户目录尚不存在且旧应用路径有本地 `scripts/` 时，才完整复制一次旧文件与标签，不删除源目录。以后启动不再重复复制，避免恢复用户已删除或修改的文件。主程序仓库不再维护 `scripts/` 副本或导入原版脚本的工具，该路径已加入 Git 忽略规则；脚本发布统一由独立脚本仓库维护。

安装元数据为包目录中的 `.rng-package.json`，记录上游文件哈希与已安装版本。通过当前文件、已安装基线、待安装版本三方比较识别本地修改（含用户删除的文件和标签改动）。默认保留冲突文件；选择“备份后使用仓库版本”才替换冲突。包外个人文件保留。新版本移除的旧包文件只有在未被个人修改时才默认删除。

仓库设置 → 更改脚本目录 → 选择空文件夹 → 迁移并使用此目录。支持换盘；脚本、标签、安装记录及安装备份一起复制并校验，成功后各窗口立即使用新目录，原目录保留为备份。配置保存在 `userData/script-storage.json`；设置保存失败仍使用原目录，已完成的复制保留供恢复。新旧目录不能相同或互相包含，不接受链接或非空目标。预览后文件改变需重新选择；运行中或存在未保存脚本时禁止迁移。配置磁盘不可用时明确报错，不静默创建另一套脚本库。

更新先在脚本目录的 `.rng-repository/staging/` 写临时完整目录，再将旧包移动到同盘 `.rng-repository/backups/`，最后替换安装目录，避免换盘后的 EXDEV 错误。该内部目录不在脚本库展示。失败会回滚；中途退出时根据安装日志在下次访问仓库时恢复，也兼容旧用户配置目录中的恢复记录。备份位置显示在安装结果与日志中心，备份不会自动清理。关闭程序会等待正在执行的文件事务结束。

脚本保存、标签保存与包安装共享写锁。手动脚本和自动流程运行期间禁止安装，更新期间禁止启动脚本。未保存的编辑缓冲阻止界面确认安装；磁盘在预览后改变时必须重新预览。

## 发布格式

索引 `catalog.json` 使用 `schemaVersion: 1`，列出名称、ID、版本、最低应用版本、游戏、作者、安装目录和 ZIP 地址、大小、SHA-256。可附带 `readme`、`updatedAt` 和逐文件清单（含 `category`），用于安装前浏览；旧索引缺少清单时从校验通过的版本包中读取。ZIP 包含 `manifest.json` 与 `files/`，描述清单逐文件记录大小和 SHA-256。说明以 Markdown 渲染，忽略原始 HTML 并限制链接协议。

下载限定两个官方源；校验大小、哈希、路径、扩展名和最低版本。拒绝穿越目录、符号链接、大小写冲突、未声明文件和超量解压。手动检查并确认更新，未实现后台自动更新、卸载、自定义仓库和分享链接。

仓库设置可选择 GitHub 或 Gitee（`https://gitee.com/shekongsk/auto-poke-rng-scripts`），选择会持久化，两个渠道的目录缓存分别保存。公开下载不需要用户输入令牌。切换渠道不修改已安装文件，尚未确认的安装预览会失效。

桌面下载使用 Electron 的网络会话，遵循系统代理设置。GitHub 原始文件地址不可达时尝试同一仓库的官方接口；Gitee 允许一次跳转到官方 `raw.giteeusercontent.com` 的同路径 HTTPS 资源，跳转前后共用下载超时，继续执行大小与哈希校验。失败时可切换渠道，或导入已下载的压缩包。网络通道回归：`node tests/run-electron.cjs script-repository-network-electron.cjs`。

## 验证

`npm run test:scripts:repository` 覆盖完整包安装、真实 `.txt` 编译、旧后缀兼容、离线缓存、三方冲突、备份与回滚、中断恢复、迁移失败、IPC 隔离、包校验与界面确认流程。Electron 集成测试：`npm run build` 后执行 `node tests/run-electron.cjs script-repository-electron.cjs`。

空库回归验证新用户初始化、浏览与预览不安装、确认安装后出现脚本，以及旧脚本和图像标签仅迁移一次。编译兼容测试使用 `third_party/bdsp-automation-reference` 中的冻结参考样本；应用不会加载或复制这些测试样本。完整官方脚本包从仓库下载后，执行 `npm run test:scripts:package -- <ZIP 路径>`，在临时目录校验、安装并逐个编译，结束后清理临时文件，不执行脚本或接触用户脚本库。

新增验证包括中文游戏分类、当前游戏默认值、用途树和文件列表、安全说明渲染、离线浏览与重试、Gitee 渠道持久化及缓存隔离。脚本仓库的 Gitee 同步工作流引用仓库级 Secret；主项目的同名 Secret 不会继承。已配置脚本仓库凭据，并验证实际同步推送及两渠道的下载、校验和安装。

测试版本编号调整属于一次性发布配置，不新增固定版本号的回归测试；通过现有构建及仓库测试、重复构建哈希一致性、索引与 ZIP 清单一致性、脚本及标签逐字节比较，以及两个公开渠道的临时目录安装验证。

独立包与目录迁移回归覆盖：嵌套包的发现、互斥目录与父级链接检查；旧脚本、个人标签及删除的三方迁移；预览后源文件变化；换目录后的旧预览失效；配置写失败及离线磁盘；同盘事务与嵌套安装中断恢复。真实 Electron 测试验证根目录切换后编辑、运行解析、主窗口和分离窗口标签读写、安装更新、旧自动配置持久化均一致。`test:scripts:package` 接受多个 ZIP，除了逐个编译，也通过运行时编译器和图像解码器检查真实标签依赖，独立包拒绝多余标签，全程不执行按键。
