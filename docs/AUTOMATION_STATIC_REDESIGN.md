## 4. 完整流程管理

- 名词：顶层叫“流程配置”，下层叫“配置组”，避免同名。
- 下拉框切换整套配置。显示当前配置完整名称，长名称截断但可查看全名。
- 新建弹窗标题“新建流程配置”，一个名称输入框，底部取消/创建。去除首尾空白，1–40 字符，重复名称就地报错；支持 Enter、Escape。
- 新建生成基本默认流程并激活，只包含必要组，不悄悄复制当前流程的可选功能。当前代码 create 是复制当前配置，需要明确改造并测试此行为。
- 重命名只改变名称，不改变 id、参数、脚本和组状态；预填当前名称。
- 删除弹窗带当前名称，确认后删除并切换到有效流程；至少保留一套配置。删除不清除跨流程共享的历史样本或日志。
- 切换和新建前保存当前有效草稿，失败则留在原配置并保留草稿。草稿完整性不同于运行就绪：允许保存尚未选择脚本的配置，但无效数字等不可静默转为合法值。
- 删除当前配置的确认已覆盖丢弃其草稿，不再叠加无意义的重复询问。

## 5. 添加与移除配置组

- 左栏加号 tooltip / accessible name 为“添加配置组”，不能与“新建流程配置”混淆。
- 弹窗标题“选择添加的配置组（可多选）”，每行复选框、名称、一句用途；底部取消/添加（N）。未选时禁用添加。
- 可选项：自动反查、过场、同步策略、逃跑续搜。闪光判定固定为必选配置组；出闪录像是其中的开关。
- 已添加项显示“已添加”且不可重复添加；全部添加时展示明确空状态。取消和 Escape 不修改配置。
- 添加后立即显示可编辑字段，在本流程持久化；不覆盖此前保存的该组参数。定位首个新加组。
- 组头提供移除和折叠。可选功能由已有设置决定是否参与运行：反查、过场、逃跑需要选脚本；同步策略需要设置队首或同步模式。未配置时不参与运行，不另设启用开关。
- 移除从当前流程显示和运行配置中移除，保留该组最后填写值，重新添加可恢复；提供轻量“已移除 / 撤销”反馈，无须每次确认。
- 持久化记录是否已添加，运行时根据组内设置推断是否生效；移除后保留草稿，重新添加可恢复。
- 单组展示“待配置 / 已配置”状态；总检查可定位到相应配置组。

## 6. 字段归属与依赖

| 组 | 字段与行为 |
| --- | --- |
| 基础设置（必选） | 流程起点；默认测种配置（旧流程默认使用当前眨眼配置）；单次/循环次数/无限循环；搜索范围；delay 策略与基准值；最大等待帧数。校正帧数上限、校正最大尝试、失败处理、补救测种次数放本组“高级设置”。自动搜索从 0 帧、Offset 0 开始，不提供初始帧或 Offset 输入。 |
| 基础脚本（必选） | 测种、撞帧、过帧脚本。脚本组始终显示，但测种脚本是否运行必填继续按起点和循环模式判断，不人为收紧既有规则。 |
| 自动反查 | 自动反查脚本、反查窗口（标明帧数单位）。 |
| 过场 | 过场预留帧数、过场脚本、过场测种配置（默认继承流程的默认测种配置）。停用后不执行过场，也不因残留过场配置失效而阻止启动。 |
| 同步策略 | 集中展示队首特性、同步模式、按模式需要的性格。先核实 lead、sync_mode、sync_nature 在搜索和运行时各自的语义，避免重复性格或互相矛盾的两个入口；不要擅自把普通队首/同步队首/迷人之躯合并成一种算法。 |
| 逃跑续搜 | 逃跑脚本；未出闪时使用闪光判定结果，保持原来续搜语义。 |
| 闪光判定（必选） | 判闪阈值、校准入口与采用建议阈值；“自动录像”开关。打开时直接执行 `CAPTURE 5000`，无需录像脚本。 |

- 判闪始终启用，阈值只在必选的闪光判定配置组编辑。自动反查和逃跑续搜只消费判闪结果，不管理阈值或校准。
- 旧流程迁移时移除录像脚本和初始帧/Offset 字段，保留原来的默认出闪录像行为；用户可通过开关关闭录像。
- 不要通过将字段设置为 0 来冒充关闭过场。根据真实执行条件生成有效运行配置。
- 一般只校验和编译启用组实际使用的脚本；停用组的残留缺失文件不应阻止运行。基础脚本依旧遵守实际必填条件。

## 7. 保存、运行和错误行为

- 使用一个清晰的“保存配置”入口与“已保存 / 未保存 / 保存中 / 保存失败”状态，覆盖当前流程的参数、脚本和配置组状态；去掉分散的“保存任务参数”“保存脚本选择”重复入口。
- 完整保存应原子化或保证失败不留下半套配置。成功后再切换流程或显示成功；异步回包不能写进其他流程。
- 开始运行前保存并检查当前配置，检查和运行应使用同一份规范化的有效配置，不能前端过滤了而后端/worker 仍读取旧脚本。
- 保存中禁止重复提交。运行/启动/停止中锁定流程切换、新建、删除、改名、配置编辑和增删组；停止与日志仍可用。真实异常要可见，不只写 console。
- 数字显示单位、合法范围和就地错误；保留空输入的编辑状态，不即时把空输入变成 0。
- 名称/脚本不存在等错误明确定位。所有图标按钮有 tooltip、accessible name 和键盘焦点，弹窗遵循已有 Dialog 的 focus/关闭规则。

## 8. 配置隔离、delay 和旧数据迁移

已确认现状：staticGroups 每项持有 config，config.static 是当前项镜像；delay 策略与样本存在 profiles[speciesId]；当前默认判闪阈值为 4，auto_reverse 默认 false；已有完整流程的新建会复制当前配置。

- 新配置的组组成、启用状态、字段、脚本全部按流程 id 隔离，重启后不丢失。不要只放 React state/localStorage。
- delay 策略和参数需要属于各自的完整流程，避免编辑 A 的策略悄悄修改 B。历史测量样本可保留现有按物种共享，界面明确标注“当前宝可梦共享样本”；清空样本需说明影响该物种的所有流程。
- 旧的每物种 delay profile.config 迁移为相关旧流程的初始策略副本，保留全部样本；以运行实际采用的逻辑为准处理 fixed_delay 与 baseline_delay 的优先级。新流程采用默认固定策略，不隐式借用另一流程正在编辑的策略。保持每轮 delay 冻结的运行契约。
- 旧文件无组状态字段时，一次性根据有效功能和有意义的旧值推断，并保留原来运行行为：auto_reverse、escape_continue、sync_mode/lead、过场脚本/过场测种配置、录像脚本、独立判闪等分别考虑。
- 仅默认存在 reseeding_threshold 或 reverse_lookup_window 等数值不能代表功能已启用；有脚本但未启用的旧反查功能，应保留脚本草稿但不要迁移成启用。
- 检查所有已保存流程，不能只迁移活动项；迁移幂等、保留 id/名称/选中项/目标/过滤器/脚本/策略/样本及 TID 配置，不损坏用户文件。
- 独立的持久化草稿和有效运行配置要有明确边界，建议统一 helper 负责运行投影，供检查和启动复用。增加 schema 字段时同步默认值、加载合并、save 白名单、IPC、类型与 worker 参数转换。

## 10. 实施与验收

按适用 Frontend App Builder、React best practices 和 frontend testing 技能工作。视觉设计覆盖主界面的默认/已添加组状态、添加组弹窗、新建/重命名/删除弹窗、停用/待配置、窄工作区；利用原图和现有主题完成可实现的设计，避免营销页元素。用户已批准开发方向，不要停在方案或原型上。

关键验收路径：

1. 新建 A，只出现必要组；名称空白/重复正确报错。重命名和删除正确，最后一套不可删除。
2. 多选添加自动反查和过场，只新增对应组；取消无副作用，已添加项不可重复选。
3. 配置脚本与参数，停用后值保留但执行和就绪检查不使用；移除/撤销/重新添加能恢复。
4. 创建/切换 B，A/B 的组、参数、脚本、delay 策略互不串用；重启恢复。共享样本行为如界面说明。
5. 旧多流程数据迁移保留运行行为，覆盖默认判闪非空但反查关闭、旧队首特性、过场和 disabled 残留脚本等边界；迁移重复加载无损。
6. 保存失败不切配置、不丢草稿，不出现部分写入；快速切换/重复点击无错配。开始使用当前配置并锁定编辑，停止正常。
7. 判闪的多个消费者共享一个一致值；关闭反查不误关逃跑续搜所需判闪。过场关闭后不执行也不检查停用脚本。
8. 原有目标过滤、校正、delay 样本/估计、候选表、日志与 TID 仍可用；所有新增按钮实际工作。
9. 在常用桌面尺寸与 1100×680 窗口（含旁侧视频/日志）检查，无横向溢出、遮挡、无法触及的弹窗按钮；完成键盘操作检查。

运行构建与针对性单元/组件/持久化/IPC 回归；改运行投影或 worker 时补契约回归。实际命令从 package.json 核对，至少 npm run build、相关 Vitest（推荐 --maxWorkers=1）、配置组 Electron 和自动流程相关检查。不要为纯视觉尺寸编写机械测试，不要连接真实串口、操作真实游戏或发送 QQ 消息。Electron 测试用隔离数据和模拟设备。
