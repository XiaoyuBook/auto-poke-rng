# 虚拟手柄的全局键盘控制

桌面版从顶部手柄菜单或脚本编辑器打开的透明 Joy-Con 浮窗，共用 `ControllerInputManager`。它启动独立的 `runtime/python/keyboard_host.py` 进程，通过 Windows `WH_KEYBOARD_LL` 捕获映射按键，与参考项目 EasyCon 的全局键盘钩子采用同一捕获范围。捕获不依赖主窗口、脚本编辑器或浮窗获得焦点，主窗口最小化时仍可控制；浮窗本身设置为不获取焦点。

- 启用：映射按键发送到手柄并被钩子消费，当前前台程序不会收到这些键；未映射键正常传递。
- 待机：不发送手柄输入，映射键恢复传递；`Esc` 仍可全局重新启用。
- `Esc`：启用／待机切换；`Ctrl+Esc`：关闭浮窗、停止捕获并释放手柄输入。
- 打开按键映射时暂时停止捕获，关闭设置后恢复先前状态；脚本占用期间进入待机，断开设备后停止捕获。

页面内的 `Controller` 是旧面板／浏览器回退界面，使用 DOM 键盘事件，依赖页面焦点。完整桌面版的透明浮窗走独立的 Windows 钩子，不经过这条路径。

## 回归验证

在有交互桌面的 Windows 环境执行：

```powershell
npm run test:controller-keyboard
```

测试加载完整生产 Electron 主程序，从顶部菜单打开手柄，仅串口使用 C++ mock。另一个 Python 进程创建前台窗口并注入系统级键盘输入，每次注入均验证 Windows 前台窗口仍属于该进程。覆盖按钮／摇杆按下与松开、启用时消费映射键、未映射键透传、待机透传、Esc 恢复、主窗口最小化和 Ctrl+Esc 关闭后恢复输入。测试使用 F23／F24 映射，避免捕获日常打字，并在退出时释放测试按键。前台窗口需要本机 Python 的标准库 Tkinter；测试会短暂将该窗口置前并在必要时点击它取得焦点，不适合无交互桌面的 CI。

2026-10-07：上述真实 Windows 钩子 → Electron → C++ mock 报告链路验证通过。此结果验证后台键盘捕获，不代替实体单片机／Switch 验收。
