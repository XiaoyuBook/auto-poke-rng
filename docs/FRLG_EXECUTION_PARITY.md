# 火叶野生／静态完整执行接入

原版锚点为 `5a5383ff226059cbf85f0b531c9de283f7b76c45`，基础资源来自 v0.9.4.1 发布包，经该提交的原版升级器处理后，再应用下文记录的菜单定位修复。生成器及扩展资源内置在应用，完整 ECS 包在 `auto-poke-rng-scripts` 发布，来源与本地修复指纹分别记录。运行不导入相邻项目源码，不启动外部 EasyCon 服务。

## 用户入口和业务边界

1. 在脚本库安装「火红叶绿／野生／静态自动流程」0.0.2。
2. 在火叶首页选择存档，连接伊机控和 **1920×1080** 视频源；按脚本包说明准备游戏、队伍、神奇糖果、球袋和重要道具。
3. 在火叶独立「自动流程」页设置目标并搜索；推荐方案位于目标卡右侧。选择正式／时间轴入口及运行参数后开始。
4. 每次从可信搜索结果生成独立工程，再校验脚本、所有引用标签、OCR 和视频。执行原版捕获、读数／吃糖、反查、候选筛选、Seed／帧校准和重试分支。
5. 页面显示执行位置和最近日志；完整日志进入公共日志系统。停止、紧急停止、设备异常或关闭窗口均结束执行并释放输入。

覆盖原版支持的普通野生、冲浪、钓鱼、狩猎区可运行路线，以及御三家、化石、礼物（含波克比）、游戏厅、普通定点、传说、事件和游走目标。原版判定不可自动运行的碎岩、狩猎区冲浪继续只允许搜索。孵蛋和独立 SID 采集不属于本次野生／静态入口；共享资源中保留其原始函数，未把它们伪装成本次完成项。

运行设置包含麻痹、点到为止、出闪后继续抓捕、非目标闪停止、Switch 录像、野生携带道具／队伍空位、Seed 启动／校准方案、帧奇偶、分层扩窗和波克比独立 Seed 反查窗口。ROM 语言和 Switch 机型由搜索存档派生。修改存档使旧方案失效，运行中冻结当前请求。

## 复用与隔离

FRLG 生命周期由 `electron/frlg-automation.cjs` 管理，使用应用自身设备锁、原生伊机控、视频帧、公共 ECS 解释器、OCR、日志和通知。珍钻业务状态、参数、反查与校准不参与火叶流程。

每次工程位于用户脚本库 `.frlg-runs/<runId>/`，避免覆盖脚本包和上一轮运行。当前保留工程供排错，未自动删除；长期使用会积累磁盘空间。预校准位于应用用户数据 `frlg/profiles/<profileId>/precalibration.json`，并按原版 ROM、机型、入口、启动方案和校准上下文进一步隔离。只有启用保存、正常结束且存在完整成功标记时更新，停止／失败不写入。

OCR 使用本应用已有 PP-OCR，支持原版 `frlg_battle` / `FRLG_EN_ALL` 语言标识映射，继续执行原版名称后处理和单字标签回退。原版专用 Tesseract 模型原样保留并验证来源指纹，但当前未由公共 OCR 加载。**OCR 后端不同，因此离线通过不能证明实机识别率与原版相同。**

## 测试资产

- `npm run test:frlg:execution`：内置生成器指纹、公共解释器兼容和 FRLG 生命周期。覆盖生成期间取消、重复开始、异常发送方、设备断开、提前完成事件、失败不保存和设备释放。
- `tests/frlg-generated-runtime.py <脚本包 files 目录>`：检查 33 项脚本／库、1154 个标签、全部引用标签的图像和 1080p 坐标；10 种野生／静态／日文目标生成编译，覆盖两个入口；实际原版 ECS 生成 PID／IV、读入已知捕获个体并扫描得到 `7422 / 25296`，偏差 2 帧时更新校准并重试、精确命中停止；成功预校准按存档和上下文隔离。该目录也可来自安装包解压，不要求原版源码。
- `FRLG_SCRIPT_PACKAGE=<发布 ZIP>` 配合 `npm run test:frlg:electron`：实际安装 → Electron → 生成器 → 公共 Python 执行器 → 原生模拟设备 → 停止／释放；截图验证目标、方案、运行日志及窄窗布局。
- `node tools/check-script-package.cjs <发布 ZIP>`：生产安装校验、临时安装、两个入口编译和资源引用检查。
- `npm run test:rng`：保留 467 组原版计算对照、65536 初始 Seed 索引以及完整结果契约。

接入时已复现并修复公共解释器的三个缺口：字符串／数组 `IN`、函数参数局部修改、已声明全局 FOR 计数器被局部变量遮蔽。最后一个缺陷会让反查找到个体却记录帧数 `-1`，最小回归修复前失败，修复后由真实原版扫描和校准函数共同验证。新增标签预检可在发出按键前拒绝损坏图片或不合适的视频尺寸。

尚未进行真实 Switch 的完整捕获验收，尤其是各地点 OCR、搜图阈值、随机场景和硬件时序。扫描／校准离线测试使用真实脚本函数及记录个体，跳过摄像头和手柄操作，不能称为实机全路线通过。自动脚本中的反查仍走原版 ECS 扫描；此前 planner 的 Python 优化不等于此路径已经加速，没有宣称 C++ 加速或固定秒数。

本轮公共模块复核：54 项 Node 自动流程适配测试、7 项 OCR／标签测试通过。原有 `test_reverse_reads_notes_then_turns_and_retries_stats` 的旧断言未过滤 `activity` 事件，因此失败；在修改前 `0c47bf6` 导出的同一测试中复现，未更改珍钻业务或该断言。没有把整个 `test:automation:adapters` 命令报告为通过。

## 第0轮菜单定位修复（0.0.2）

上游 `325147a` 的快捷登记扩展错误地用“向上8次”给火叶循环主菜单归零，导致普通冷启动再向下5次实际进入 SAVE，随后文字速度标签无法匹配。旧发布包经源码升级器处理后也会包含这段逻辑，因此不能只根据原始 ZIP 版本声称运行脚本相同。

应用在固定上游提交上保留可复现的本地补丁 `tools/frlg-runtime-patches/menu-navigation.patch`，再次导入上游时自动重放，并分别记录来源提交、补丁和最终文件指纹。两个主入口现在保持无快捷登记时的原始路径；快捷登记从冷启动位置进入背包，返回后从背包向下3次进入选项。生成运行工程时也迁移已安装的 0.0.1 模板，只修改新工程。脚本库 0.0.2 则供直接运行和新安装使用；历史 `.frlg-runs` 不覆盖，重试时应重新生成。

菜单回归通过公共 ECS 解释器执行真实按键，在循环菜单模型上检查实际进入的页面。冻结用户成功脚本的原始选项入口作为对照；原生成器在普通／御三家冷启动用例均失败，修复后通过。实际包的正式／时间轴入口覆盖无快捷、TV、自行车、钓竿，并用 NS2、B744、11985 帧皮卡丘参数验证旧模板生成后的设置流程。该验证不代表真实 Switch 的图像识别或按键时序验收。
