# 珍钻复刻御三家全自动

自动流程页选择草苗龟、小火猴或波加曼，在“基础脚本”组开启“御三家全自动”。
该模式不需要选择测种、过帧、撞帧或反查脚本。关闭此选项后恢复原有自选脚本模式，
原脚本和可选功能配置保留。已有配置不会被自动切换。

全自动开关位于卡片标题栏，开启后卡片仅显示反查窗口设置；执行原理与固定时序见本文。
草苗龟、小火猴、波加曼默认使用固定 **66 帧**，其他定点仍为 **100 帧**；首次创建的
物种 delay 配置使用对应默认值。切换目标时，仍在使用默认固定 delay 的流程跟随目标
更新数值，已调整的固定值和动态策略保留；读取已有配置时不覆盖保存值。

眼睛模板、ROI、源分辨率和关闭菜单 +1 沿用选择的眨眼配置。运行时自动采用用户截图
提供的时序，不改写保存的眨眼配置：

| 参数 | 值 |
| --- | ---: |
| Threshold | 0.7 |
| Time Delay | 0 |
| Advance Delay | 41 |
| Advance Delay 2 | 48 |
| NPCs | 1 |
| NPCs during Timeline | -1 |
| Pokemon NPCs | 2 |

## 执行顺序

1. 从测种脚本开始：运行内置 `seed.ecs`，复用已有共享帧眨眼捕获与 Seed 求解。
   也可从当前游戏起点直接捕获 Seed；本模式不提供从已过场 Seed 校正开始。
2. 锁定目标后接管：复用放大模式两次确认、双 HOME、退出复查；确认
   “怎么回事？刚才那两人……”。随后按录像时间固定发送 8 次普通 A，
   到博士对白再用 OCR 确认；省略号页和进入草丛的动画包含在该固定序列中。
3. 停在“就是想还也不知道对方是谁啊，虽然有听到叫博士……”；
   到目标 RNG 帧减 **200** 时自动请求 Timeline。200 是代码常量。
4. 沿用 Project_Xs 第一段倒计时，在 Timer 从 1 变成 0 时立即按 A。
   3470ms 后发送 1 次普通 A，再用 OCR 确认“搞什么啊！”。
5. 第二段同样在 Timer 从 1 变成 0（第 10 个 Timeline 事件）时立即按 A，
   4840ms 后发送 1 次普通 A，再用 OCR 确认“要选哪一只？”。
   下一事件的 48 Adv 补偿沿用 Project_Xs 原时序。
6. 确认“要选哪一只？”后，立即将光标移动到目标精灵球：草苗龟不移动，
   小火猴向右 1 次，波加曼向右 2 次。向右每次按住 100ms、松开等待 120ms，
   此时只移动光标。定位完成后等待目标 RNG 帧减**本轮实际 delay**，
   再按 `A → 等待 800ms → ↑ → 等待 100ms → A` 打开确认、选“是”并确认。
   最终动作由常驻手柄进程执行，每次按住 50ms，与 ECS 裸写 `A`、`UP` 的默认时长一致；
   两次等待从前一个按键松开后开始，等待期间按键处于松开状态。
7. 复用现有“去吧/上吧”→“战斗”判闪；出闪按原规则录像并停止，结果未知停止。
   未出闪运行内置 `reverse.ecs`、OCR 反查、保存 delay 样本，再按循环设置处理。

delay 使用现有策略，每轮开始读取并固定一次。反查样本仅影响后续轮次，
不临时改写已锁定目标的 delay。测种和反查 ECS 原文及许可来源见
`resources/automation/bdsp-starter/README.md`。

内置反查当前同步官方 `bdsp-starter-reverse` 0.0.5 包，采用 2026-10-08
本机脚本库的摘要阶段修订。脚本包与内置反查逐字节一致，集成回归校验目录索引
中的长度和 SHA-256。自动流程继续通过内置身份加载反查；更新后重新开始流程，
已有运行保留启动时的脚本快照。

## 时序约束与停止

两段倒计时和转换消耗的计数为 `11 × (1 + 1) + 41 + 11 + 48 = 122` Adv。
因此此预设要求实际 delay **小于 78**，还需要给精灵球过场留出时间。
软件不会将 200 拉大或截断 delay：固定策略在启动检查时报错，动态策略在每轮
固定实际值时检查。旧撞帧脚本的 delay 样本未必适用于新的快速选择动作，
应使用该动作对应的御三家 delay。

最终确认阶段按用户实测脚本保留 A 后 800ms 和向上后 100ms 的松开等待，
每个按键保持 50ms。向右移动及松开后的等待已提前到光标定位阶段。
这组确认时序需要重新校准 delay；原先无等待或包含向右操作的反查样本
不能代表新时序，此前较慢选择动作的样本同样不能代表当前时序。

固定序列的普通 A 保持 200ms；两次计时归零 A 保持 100ms。完整录像按下、松开、
间隔及逐页对应记录见 [`BDSP_STARTER_RECORDING_TIMING.md`](BDSP_STARTER_RECORDING_TIMING.md)。
起点后的 7 个按下间隔为 3540、1870、900、870、670、5000、1140ms。

对话确认与时钟运行分离。OCR 只在起点和三个关键位置检查实际白色对话正文，
固定按键序列及等待计时阶段暂停识别，恢复时丢弃前一阶段的在途结果。计时线程按共享的
Project_Xs RNG 时钟调度；它不依赖 React 状态刷新或 OCR 完成时间触发倒计时按键。
两段 A 都使用计数首次归零的时间戳，Adv 补偿按原版后续节点计算。归零后处理过晚
会记为错过目标，避免用更晚的切换或补偿节点补按 A。
光标定位前后都会更新 RNG 时钟；到达选择帧才开始定位，或定位完成时已到达、
超过选择帧，都视为错过目标。定位失败或中途停止不会执行最终确认。
错过启动、倒计时或选择节点时不选择精灵，本轮记录“错过目标”，按已配置循环
继续或结束。对话、视频源、OCR 或手柄故障明确停止；停止释放控制动作。
